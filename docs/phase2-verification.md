# Phase 2 검증 리포트 — 어노테이션 + CapNote 실기기 E2E

- **일시**: 2026-07-02
- **결론**: **검증 통과 — Phase 2 완료.** 실제 앱 산출물(번인 PNG + CapNote 블록)을 실제 Claude Code에 ⌘V로 붙여넣어 마커 3종 지목을 확인. 사용자 실사용 판정: 마커 의도 일치 · 체감 속도 문제없음.
- **방법**: Phase 0과 동일 방식. 실기기에서 ⌥⇧C → 터미널 화면 캡처(@2x) → 스마트 툴로 rect/point/arrow 3종 + 노트 입력 → ⌘⏎ → Claude Code에 ⌘V. 이후 정답을 모르는 **블라인드 에이전트 1개**에게 블록만 전달해 지목 확인.

## 1. 산출물 검증

대상: `~/.capnote/2026-07-02-225238.png` + 앱이 생성한 CapNote 블록.

| 항목 | 기대 | 실측 | 판정 |
|---|---|---|---|
| 다운스케일 | @2x 캡처 → 1/2, 장변 ≤1568 | 원본 2056x800 → 저장본 1028x400. 헤더 `size: 1028x400` = `sips` 실측 일치 | ✅ |
| `scale:` | 표준 정책상 1:1 | `1 image px = 1 CSS px` | ✅ |
| 좌표 정합 | 텍스트 좌표 = 번인 위치 | `[2] point (389,143)` 링 중심이 크롭 실측과 픽셀 단위 일치 | ✅ |
| 번인 스타일 (동결 A4) | 배지 오프셋+리더, rect 점선+아웃셋, point 링 | 3종 모두 스타일대로 렌더 | ✅ |
| 노트 비번인 | 노트는 텍스트 채널 전용 | 이미지에 번호·도형만 존재 | ✅ |
| 번호 시퀀스 | 도구 무관 단일 증가 | rect=[1], point=[2], arrow=[3] | ✅ |

## 2. 블라인드 에이전트 지목

| 마커 | 결과 |
|---|---|
| `[1] rect` | 감싼 영역의 텍스트를 정확히 인용 ✅ |
| `[2] point` | 링 위치 정확히 특정 ✅ (단어 명명은 11px 터미널 한글이라 편차 — 비전 해상도 한계이지 포맷 문제 아님. 대표 시나리오의 UI 요소는 훨씬 큼) |
| `[3] arrow` | 꼬리→머리 방향과 머리가 가리키는 단어("feature", x=391 라인 실측 일치)를 정확히 지목 ✅ |

배지 번호·좌표·텍스트 정합성 확인, 파싱 오류 없음.

## 3. 실측 발견 3건

1. **Claude Code가 붙여넣은 텍스트 속 이미지 경로를 자동으로 이미지 첨부로 치환** — `image:` 라인이 비어 보이지만 첨부 source가 정확히 그 경로. 시각 채널이 Read 도구 없이도 자동 도착(설계 의도 초과 달성). 이 거동은 외부 가정(리스크 #8)으로 계속 관찰.
2. **asset protocol은 캔버스를 taint시킴** — `convertFileSrc` 로드 이미지는 webview 오리진 기준 교차 출처라 커밋 시 `toBlob()`이 SecurityError. 캡처 로드를 Rust IPC(`load_capture_png`, base64 → same-origin `data:` URL)로 교체하고 asset protocol 설정 제거로 근본 해결 (`14bf1d1`).
3. **배지가 이웃 줄 텍스트를 가리는 케이스 실측 확인** (리스크 #5 그대로) — 오프셋 배지가 밀집 텍스트에서 윗줄 글자를 덮음. 링이 실제 대상을 정확히 표시하므로 기능 문제는 없음. 충돌 회피 배치는 계획대로 Phase 3.
